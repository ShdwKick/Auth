# Минимальный сервис, подключённый к общему аккаунту

Настоящий запускаемый пример к [../../INTEGRATION.md](../../INTEGRATION.md): сервис
хранит одну заметку на пользователя. Всё, что относится к авторизации, здесь
сведено к минимуму — из этого можно копировать в новый проект.

| Файл | Что смотреть |
|---|---|
| `server.js` | `auth.userFromRequest(req)` — вся проверка токена в двух строках; `/api/config`; `notes` под ключом `user.id`, а не логина |
| `index.html` | `handleRedirect()` до первого запроса, `auth.fetch`, обработка `AuthRequiredError`, ссылка в кабинет |

**Одно отличие от реального проекта:** пример подключает библиотеки из `../../client/`
напрямую, чтобы две копии внутри одного репозитория не разъехались. В настоящем проекте
эти два файла копируются к себе — `auth-client.js` рядом с `server.js`,
`auth-client-browser.js` в `assets/` (см. шаг 2 в [INTEGRATION.md](../../INTEGRATION.md)).

## Запуск

Нужен работающий auth-сервис. Проще всего поднять его локально из корня репозитория:

```bash
DEV=1 ISSUER=http://localhost:8788 node server.js
```

Зарегистрировать этот пример как клиента (там же, в корне репозитория):

```bash
node server.js client-add example "Пример" http://localhost:8789/
```

Запустить пример:

```bash
cd examples/minimal-service
AUTH_ISSUER=http://localhost:8788 AUTH_CLIENT_ID=example node server.js
```

Открыть <http://localhost:8789> → «Войти» → зарегистрироваться или войти →
вернётесь обратно, заметка сохраняется автоматически.

Если auth-сервис уже открыт в этом браузере, пароль спросить не должны вовсе —
это и есть SSO. Проверить можно так: войти в «Мои финансы», затем открыть этот
пример; вход должен пройти без формы.

На Node 22 добавьте `--experimental-sqlite` к запуску auth-сервиса (самому примеру
SQLite не нужен, он держит заметки в памяти и теряет их при перезапуске — это
пример авторизации, не хранилища).
